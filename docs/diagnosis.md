# 诊断：你的卡顿是哪一种？

海外B站卡顿本质上说有两种问题，网上教程几乎只讲第一种。

| 问题 | 症状 | 解决方法 |
|---|---|---|
| **A. CDN家族选错**：B站把你分给了整体表现差的CDN厂商 | 换一家CDN（油猴脚本切换域名）后明显好转 | 油猴脚本，如 [CCB](https://github.com/Kanda-Akihito-Kun/ccb) |
| **B. 节点分配错**：CDN没问题，但DNS把你解析到了远端/超载/死掉的节点 | 换哪家CDN都一般，甚至默认源整个超时 | **本项目**：找出最快节点 |

## 诊断方法：B站官方测速页

播放任意视频后，访问：

```
https://www.bilibili.com/blackboard/webplayer/speed.html
```

注意：测速用的是"最近一次观看记录"的地址，所以要先看一会儿视频再测。

看"服务器"和"延迟"两列：

- 某个域名**所有行都超时**（5999ms）→ 问题B，你被解析到了死节点，本项目直接救命
- 延迟普遍 **300ms+** → 问题B，被派去了远端节点
- 换了CDN域名后**某家明显快** → 问题A，用油猴脚本即可
- 晚高峰时段测最有参考价值；两种问题可以并存

## 真实案例

澳洲 Opticomm 千兆宽带：默认 Akamai 源全线超时（0 Mbps），720p都看不了。诊断发现 Akamai 在悉尼本来就有 3ms 的本地节点，只是DNS从来没把用户带过去。钉住该节点后测速 **571 Mbps**，4K秒开。

同场加映：akamTester 的全球IP列表里130个节点只剩3个可用——静态IP列表会腐烂，这正是本项目"实时DNS解析补充候选+定期复测"设计的原因。
